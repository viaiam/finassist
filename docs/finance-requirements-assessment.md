# 金融需求评估与本轮边界

## 尽量少改的方案

保留 API / service / engine / domain / repository 分层及任务状态机。
在原中台增加金融适配接口，读取 finassist_finance 查询数据，并通过事务写入投诉工单；模型负责规划与知识表达，业务数据由代码返回。
比重写一套金融 Agent 改动更小，也比把金融表改成订单字段更清楚。

## 本轮实现

| 需求 | 实现范围 |
|---|---|
| 账户查询 | 账户号或完整银行卡号查余额、可用、冻结金额；卡片填槽 |
| 交易查询 | 账户 + 自然日或最近记录；返回最多 20 条，标明是否截断 |
| 银行卡 | 当前样例客户的掩码卡号、类型和状态 |
| 贷款查询 | 状态、本金、未还本金、利率、期限 |
| 还款计划 | 最新版本计划，最多 60 期 |
| 产品咨询 | 样例贷款/理财产品，风险等级、额度、期限、起购条件等 |
| 多轮管理 | 沿用槽位收集、切换、恢复、取消与会话持久化 |
| 对话与前端体验 | 新建会话、当前会话状态、暂停任务提示、按当前会话加载历史；交易流水卡片可填入交易查询账户或投诉关联流水 |
| 投诉工单 | 多轮收集投诉类型、关联流水（可选）和描述；校验流水归属；工单、初审待办与持久幂等记录同事务写入；支持查询状态 |
| 对象消息 | 账户、贷款、贷款产品、理财产品 |
| 闲聊/澄清 | 全部替换为金融客服提示词 |

## 本轮不声称支持

- 贷款申请：真实材料、额度校验、写入幂等、确认和审批状态需要单独接入。
- 信用卡挂失：不能将普通银行卡状态修改冒充信用卡挂失；还缺身份验证与业务确认。
- 投诉处理闭环：本轮能提交工单并查询待初审状态；人工工作台、后续处理、通知和结案仍未实现。
- 基金、信用卡账单、独立存款产品：需求列出了概念，但当前实际表没有对应完整业务模型。
- 正式政策/RAG：尚无经审核的规则文档，手续费与提前还款只说明以实际合同为准。
- SSE、人工工作台、审计链路：需要另行扩展，不属于改提示词即可完成的功能。
- 生产鉴权：sender_id 仍由演示页面输入，不是认证身份；不能接真实客户数据。

## 验收与限制

页面会加载真实样例 customer_no，不再将 u1001 当作金融客户。
查询必须匹配当前客户名下对象，但这只是样例数据隔离，不是生产身份验证。
新版本需要重启中台与客服，前端开发服务会热更新。
原始资料中还有大量写入 API，本轮不直接暴露，避免超出最小改造范围。
